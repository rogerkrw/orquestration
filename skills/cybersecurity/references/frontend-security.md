# Frontend Security — SvelteKit / React

## XSS — Svelte's default safety + escape hatches

Svelte auto-escapes `{value}` expressions. The dangerous primitive is `{@html ...}`:

```svelte
<!-- ✅ Safe -->
<div>{user.bio}</div>

<!-- ⚠️ Dangerous — only with sanitized input -->
<div>{@html marked(user.bio)}</div>
```

When using `{@html}`:
1. Sanitize the input with `DOMPurify` (`isomorphic-dompurify` for SSR)
2. Render Markdown through a parser that escapes by default (`marked` + sanitize, or `markdown-it` with `html: false`)
3. Never `{@html userInput}` without sanitization, ever

## Token storage decision

| Storage | XSS risk | CSRF risk | Use when |
|---|---|---|---|
| `httpOnly` cookie | ✅ Safe from JS | Needs CSRF protection | Default choice for browser apps |
| `localStorage` | ❌ JS-readable | ✅ Not auto-sent | Only when XSS is otherwise impossible (e.g., pure SPA with no third-party scripts) |
| `sessionStorage` | ❌ JS-readable | ✅ Not auto-sent | Same as above, plus tab-scoped |
| Memory (variable) | ✅ Safer | ✅ | Short-lived; lost on refresh |

**Default: httpOnly cookie + CSRF protection.** Mobile/native API clients use `Authorization: Bearer` headers.

## CSRF in SvelteKit

SvelteKit form actions auto-check origin. The risk is `+server.ts` endpoints that accept JSON POSTs.

```ts
// src/hooks.server.ts
import type { Handle } from '@sveltejs/kit';

export const handle: Handle = async ({ event, resolve }) => {
  if (event.request.method !== 'GET') {
    const origin = event.request.headers.get('origin');
    const allowed = ['https://app.example.com'];
    if (!origin || !allowed.includes(origin)) {
      return new Response('Forbidden', { status: 403 });
    }
  }
  return resolve(event);
};
```

For state-changing endpoints: `SameSite=strict` cookies + origin check is enough. For higher security, double-submit cookie.

## Content Security Policy

```js
// svelte.config.js
const config = {
  kit: {
    csp: {
      mode: 'auto',  // or 'hash'/'nonce' for stricter
      directives: {
        'default-src': ['self'],
        'script-src': ['self', 'https://cdn.trusted.example.com'],
        'style-src': ['self', "'unsafe-inline'"],  // Tailwind needs this; consider 'unsafe-hashes' for stricter
        'img-src': ['self', 'data:', 'https:'],
        'connect-src': ['self', 'https://api.example.com'],
        'font-src': ['self', 'data:'],
        'object-src': ['none'],
        'base-uri': ['self'],
        'form-action': ['self'],
        'frame-ancestors': ['none'],
      }
    }
  }
};
```

`mode: 'auto'` lets SvelteKit hash inline scripts/styles it generates. For third-party widgets, add origins explicitly — never `'unsafe-inline'` for scripts.

## Environment variables — public vs. private

```ts
// ✅ Server-only, never reaches the client bundle
import { DATABASE_URL } from '$env/static/private';

// ✅ Public, baked into client bundle
import { PUBLIC_API_URL } from '$env/static/public';

// ❌ DON'T import private env in components or +page.svelte
```

Anything in `$env/static/private` or `$env/dynamic/private` MUST stay in `+page.server.ts`, `+server.ts`, `hooks.server.ts`, or `$lib/server/*`. Importing them anywhere else breaks the build.

`$lib/server/*` modules can't be imported into client code by SvelteKit's design — use this for any server-only code.

## Cookies

```ts
// +page.server.ts action
event.cookies.set('session', token, {
  path: '/',
  httpOnly: true,
  secure: true,           // HTTPS only
  sameSite: 'lax',        // 'strict' for high-security, but breaks OAuth redirects
  maxAge: 60 * 60 * 24 * 7
});
```

`secure: true` is mandatory in production; `sameSite: 'lax'` is the right default.

## Avoiding script injection from data

```svelte
<!-- ❌ Bad: user-controlled URL goes into href -->
<a href={user.website}>visit</a>

<!-- ✅ Validate scheme -->
<script>
  const safeHref = (url) => {
    try {
      const u = new URL(url);
      return ['http:', 'https:'].includes(u.protocol) ? url : '#';
    } catch { return '#'; }
  };
</script>
<a href={safeHref(user.website)} rel="noopener noreferrer">visit</a>
```

Always `rel="noopener noreferrer"` on user-controlled `target="_blank"` links.

## Third-party scripts

Subresource Integrity (SRI) on any external script:

```html
<script
  src="https://cdn.example.com/lib.js"
  integrity="sha384-..."
  crossorigin="anonymous"
></script>
```

If the CDN compromises, the hash mismatches and the browser refuses to load. SRI hashes generated by `npx srigen` or the CDN itself.

## React notes (if mixed stack)

- `dangerouslySetInnerHTML` is React's `{@html}` — same rules: sanitize first.
- `next/link` adds `rel="noopener noreferrer"` automatically for external URLs.
- React 18+ has automatic XSS protection on event handlers but not on `href` attributes — validate URLs as above.
